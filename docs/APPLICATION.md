# Самостоятельный SCALEGO: архитектура и дизайн

Реализовано в 0.1.0-alpha.1. Документ описывает самостоятельное приложение. Ранние исследования интеграций хранятся локально и не определяют возможности текущего выпуска.

## Решение о стеке

Собственная оболочка Electron/React сохраняет знакомые подходы GO-продуктов, семантические цвета и системные шрифты MPGO. Форк Upscayl не используется: задача — единая очередь увеличения и сжатия, прозрачность и проверяемый экспорт. Неизменённый Real-ESRGAN-ncnn-vulkan работает отдельным процессом; Sharp объединяет декодирование, интерполяцию и четыре выходных кодека.

Это экономит разработку inference и кодеков, но оставляет зависимость от Vulkan, upstream-бинарников, размера Electron и разных лицензий. CPU Lanczos и Nearest обозначены самостоятельными методами.

## Поток данных

1. Main получает пути из диалога или desktop drag-and-drop, проверяет файл и создаёт свою копию с UUID и миниатюрой.
2. Renderer получает ID, имя, метаданные и URL `scalego-asset`; приватные файловые пути не входят в публичный контракт.
3. Main валидирует параметры, формирует последовательную очередь и запускает worker для каждого задания.
4. Worker применяет EXIF-поворот и sRGB. Для AI передаёт RGB PNG в native runner, отдельно увеличивает alpha и соединяет каналы. Фото-модель использует native 4× с resampling для 2×/3×.
5. Кодек создаёт PNG/JPEG/WebP/AVIF. Лимит веса вызывает до семи попыток подбора качества. Недостижимый лимит становится предупреждением.
6. Worker проверяет размер результата и записывает рецепт с SHA-256. Ошибка одного задания не останавливает остальные.
7. Экспорт готовит пару «изображение + рецепт». Блокировка имени и exclusive create защищают существующие файлы. На NTFS изображение публикуется hardlink, на других файловых системах — копированием без перезаписи. Атомарность всей пары при сбое питания на fallback-файловой системе не гарантируется.

## Процессы и границы

- Renderer: context isolation, sandbox, без Node integration; ограниченная CSP, запрет новых окон и навигации.
- Preload: именованные команды, без произвольного shell или чтения файлов.
- Main проверяет отправителя IPC и main frame, enums и диапазоны на доверенной стороне.
- Worker изолирует тяжёлую обработку от окна. Native runner запускается без shell с массивом аргументов. Отмена завершает worker и runner.
- Штатное закрытие переводит активные задания в `interrupted`. Повторный экземпляр приложения фокусирует первое окно.
- Vulkan OOM уменьшает тайл 256 → 128 → 64 → 32. Неудача показывается пользователю; метод автоматически не меняется.
- Обработка не отправляет изображения на сервер. Интернет нужен для первоначальной установки зависимостей и моделей.

## Сессия и экспорт

`%APPDATA%/scalego/session.json` содержит приватный manifest; `work/` — snapshot исходников, миниатюры и папки заданий. Запись сериализуется через temporary file + rename: debounce 100 мс и принудительная запись при штатном выходе. При аварийном завершении последние незаписанные изменения могут отсутствовать.

Восстановление проверяет наличие файлов и принадлежность путей рабочей папке. Сохраняются исходники и последние 400 заданий. Внешние оригиналы можно перемещать: обработка использует snapshot. Удаление исходника из приложения очищает связанные данные рабочей области, не трогая экспорт и внешний оригинал.

`.scalego` — JSON: `schemaVersion: 1`, версия приложения, SHA-256 исходника/результата, параметры, размеры, байты, фактическое качество и предупреждения. Импорт рецептов не реализован.

Dev-переменные: `SCALEGO_DEV_URL` включает фиксированный Vite URL; `SCALEGO_TEST_DATA` и `SCALEGO_SMOKE_INPUT` работают только в неупакованной сборке. Packaged smoke использует отдельный `--user-data-dir` и файловый диалог, подменённый из тестового процесса Playwright.

## Дизайн-система

Токены: `src/styles/tokens.css`. Dark: canvas `#0d0f12`, panel `#111419`, text `#f1f2f3`. Light: canvas `#f3f2ef`, panel `#fbfaf7`, text `#222326`. Основное действие: оранжевый `#f4511e` / `#e5481c` с тёмным текстом. Цвет дополняется подписью статуса.

Segoe UI Variable → Segoe UI → Arial; числовые значения Cascadia Mono → Consolas. Body 14/21, labels 12 px, технические подписи 10–11 px. Системные шрифты не встраиваются и не скачиваются.

Композиция: toolbar 64 px, список 232 px, гибкий canvas, inspector 304 px и action bar. Панели прокручиваются независимо. На небольшом окне колонки сужаются, команды переносятся; чекбоксы выбора остаются доступны. Минимальное окно 900×640. Мобильная версия не заявляется.

Состояния: пустая область, импорт, исходник, running/queued, canceled/interrupted, ошибка, результат, изменённые параметры и предупреждения экспорта. Поддержаны focus, подписи кнопок-иконок, keyboard range и reduced motion.

## Проверка гипотез

Интервью и слепое сравнение с Upscayl ещё не проводились. Далее измерять время до экспорта, ошибки выбора режима, артефакты текста/краёв и достижение лимита веса на фотографиях, логотипах, стикерах и JPEG с сильной компрессией. Заявления о превосходстве над конкурентами не делаются.
